> 讓世界看見台灣的味道。從鹹點到甜點、從珍奶到豆漿。

純 HTML / CSS / JS 製作的單頁式官網，無需 build，雙擊 `index.html` 即可運行。

## 🎤 專案特色介紹（給組員報告用）

> 這段是「報告講稿」：每個小標下的引號內句子可以幾乎照唸；後面的 **Demo** 是要點哪裡給老師看。建議搭配「建議 Demo 流程」一節邊講邊操作。

### 0. 一句話開場（電梯簡報）

> 「我們做的是 **TAI FOOD — 台灣街頭美食的互動官網**。它不只是把菜列出來，而是把『**選擇困難、想知道哪裡有得吃、想記錄吃過什麼**』這些真實情境，做成一個個互動體驗。整個網站**純 HTML / CSS / JavaScript、不用任何框架、也沒有後端**，全部在瀏覽器跑。」

### 1. 我們在解決什麼（主題與設計理念）

> 「台灣美食很多，但使用者真正的煩惱是：**這麼多要吃什麼？去哪吃？吃過的怎麼記？** 所以我們圍繞這三個痛點設計功能，並用**紅金配色、水彩插畫、雜誌式排版**呈現台味質感。」

### 2. 八大特色（逐項：亮點口白 + 怎麼 Demo）

**① 沉浸式主視覺 + 視差**
> 「一進站是點擊開場，主視覺把台灣小吃『爆炸』散開，滑鼠移動、頁面滾動時各層用不同速度移動，做出立體景深。」
> **Demo**：開首頁 → 滑鼠在主視覺上移動一下。

**② 真實搜尋（關鍵字 + 地點）**
> 「標題問『想知道哪裡有美食』，所以搜尋是真的能回答——輸入菜名加地點，會列出**有賣這道菜的店家**，還支援同義詞（打『珍奶』也找得到珍珠奶茶）。」
> **Demo**：搜「牛肉麵」+「信義」→ 出現店家卡。

**③ 33 道美食 + 獨立詳情頁**
> 「每道菜都有自己的網址頁面，含大圖、介紹、**食材拆解**、**哪裡吃得到**、**你可能也想吃**。重點是全站菜色資料只有一份（`data.js`），改一處、首頁和詳情頁同步更新。」
> **Demo**：點任一道菜 → 看詳情頁。

**④ 滷肉飯『食材組裝』動畫**（招牌彩蛋）
> 「滷肉飯有完整的水彩分層素材，所以我們做了特別動畫：白飯、滷肉、滷蛋、蔥花、醃蘿蔔從四面八方飛入聚攏，組合成一碗完整的滷肉飯。」
> **Demo**：進『滷肉飯』詳情頁 → 看開頭動畫（可按『重新組裝』重播）。

**⑤ 甜點『圓桌轉盤』（滾動驅動）**
> 「甜點區不是傳統卡片，而是一張**會轉的圓桌**——你滾動頁面，圓桌就跟著轉，轉到正上方的那道甜點會放大打光，而且每道菜的字**永遠是正的**。」
> **Demo**：捲到甜點區，慢慢滾動。

**⑥ 飲品『展開手風琴』**
> 「飲品做成可展開的面板，滑到或點選哪一格，它就展開露出介紹，有照片的飲品還用了真實去背圖。」
> **Demo**：捲到飲品區，滑過不同面板。

**⑦ 今天吃啥（每日一食 + 月曆）**
> 「選擇困難時，按一下骰子幫你隨機決定一道，還有一個**月曆記錄每天吃了什麼**；演算法特別設計**最近三天不重複**，讓每次都新鮮。結果會存在瀏覽器，重整也記得。」
> **Demo**：捲到『今天吃啥』→ 按擲骰；指一下月曆已填滿的紀錄。

**⑧ 美食護照集點**
> 「把吃過的美食蓋章記錄、**每章累積 10 點**。最酷的是**三個地方都能打卡**——護照頁、詳情頁、今天吃啥——而且**即時同步**，點數和進度一起更新。」
> **Demo**：集點卡點幾張卡蓋章 → 點數跳動、進度條前進。

**⑨ 台味接接樂（壓軸 · 互動小遊戲）**
> 「點 header 右上角的『🎮 接接樂』按鈕就能開：各國食物從天上掉下來，你要用籃子**只接台灣美食**，接對加 10 分，**滿 50 分過關**。它故意讓不同食物用一樣的 emoji，逼你**讀名字判斷是不是台灣味**——所以也是個小測驗。隨時可按右上角『關閉』或 Esc 離開。」
> **Demo**：任一頁 header 右上「🎮 接接樂」按鈕即開（首頁 footer 也保留一個入口）。

**⑩ 網站 QR Code（分享 · header 區塊）**
> 「Header 右上多一個『掃我』小 QR 按鈕，點一下放大成可掃描的彈窗，手機相機對準就能開站（連到 `https://twfood.vercel.app/`）。QR 是**離線靜態檔** `assets/qrcode.svg`（事先產生，不靠第三方 API 即時生成，服務當機也不影響）。彈窗可點背景或 Esc 關閉。手機版會自動隱藏這顆按鈕（自己掃自己螢幕沒意義）。」
> **Demo**：桌機 header 右上「掃我」→ 放大 QR → 手機掃描開站。
> **改網址時**：QR 內容是固定快照，網址若變更需重新產生 `assets/qrcode.svg`（用任一 QR 產生器把新網址輸出成 SVG 覆蓋即可）。

### 3. 技術亮點（給老師看深度，挑著講）

- **純前端、零框架、零後端、零 build**：只有 HTML/CSS/JS，雙擊就能跑。
- **單一資料來源**：33 道菜、店家、食材全集中在 `data.js`，首頁與詳情頁共用，不會資料不一致。
- **狀態持久化**：用 `localStorage` 記住「今天吃啥的結果、護照點數」。
- **確定性演算法**：月曆過去日期用「日期雜湊」生成，所以**重整頁面結果不變**，又能保證近三天不重複。
- **事件驅動同步**：護照用自訂事件 `passport:change`，任一處蓋章，其他畫面即時更新。
- **無障礙與體貼**：可用鍵盤操作、`aria` 標註、偵測使用者「減少動態」偏好就關閉強烈動畫、遊戲隨時可按「關閉」或 Esc 離開。
- **響應式 RWD**：手機 / 平板 / 桌機都重新排版（轉盤、手風琴、月曆、護照都有手機版）。
- **錯誤全顯示在前端**：任何 JavaScript 錯誤都會在畫面右下角顯示，方便除錯。

### 4. 建議 Demo 流程（約 5–8 分鐘，邊講邊點）

1. **開場**：開首頁 → 點擊進入 → 滑鼠在主視覺上晃，講「視差主視覺」。
2. **搜尋**：搜「牛肉麵 + 信義」→ 店家卡。
3. **詳情頁**：點一道菜進詳情；接著專門開「**滷肉飯**」秀組裝動畫（招牌）。
4. **甜點轉盤**：回首頁捲到甜點，邊捲邊轉。
5. **飲品手風琴**：捲到飲品，滑開面板。
6. **今天吃啥**：擲骰 + 指月曆。
7. **集點卡**：蓋幾張章，講「三處同步」。
8. **壓軸**：點 header 右上「🎮 接接樂」按鈕玩一下。

## 一鍵預覽

> **建議：雙擊 `開啟網站.command`**（Mac）。它會自動起一個本機小伺服器並用瀏覽器打開，
> 關閉終端機視窗即停止。**這是最可靠的開法。**

```bash
# 方法 B：手動起 server（與 .command 等效）
python3 -m http.server 8080
# → http://localhost:8080

# 方法 C：直接雙擊 index.html（file://）— 不建議
# file:// 下瀏覽器把每個本機檔當「不同來源」，部分瀏覽器/擴充功能會擋掉
# CSS 套用、圖片或 cssRules，導致畫面變成「無樣式 + 圖片破圖」。
# 若一定要用，遇到破版請改用上面的 .command 或 server。
```

> ⚠ **為什麼不建議直接雙擊 `index.html`？** 靜態網站用 `file://` 開時，行為因瀏覽器/擴充功能而異
> （有人正常、有人整頁無樣式）。本專案的檔案與相對路徑都正確（用乾淨瀏覽器以 `file://` 實測可正常顯示），
> 但為了**保證每台機器都一樣**，請用 `開啟網站.command` 或本機 server 走 `http://`。
> 臨時排查：在 Chrome 用**無痕視窗**（關掉擴充功能）或 **Cmd+Shift+R** 強制重整，常能排除是不是擴充功能/快取造成。

## 台味接接樂（互動小遊戲 · `game.js`）

由使用者主動開啟的全頁小遊戲 + 台灣美食知識測驗（**不再有閒置自動跳出**）。

- **觸發**：`game.js`（index 與 dish 兩頁共用）監聽 `click`，點任何帶 `data-play-game` 的元素 → `launch()` 注入全頁覆蓋層（`z-index:9000`，低於錯誤橫幅）、鎖 body 捲動。入口為**兩頁 header 右上的「🎮 接接樂」按鈕**（`.navbar__game`），首頁 footer 也保留一個 `data-play-game` 連結。
- **玩法**：各國食物卡片（emoji + **名稱**）從上方掉落；籃子隨 `pointermove/touchmove` 跟手 + 方向鍵控制；**只接「台灣味」+10 分**（綠閃）、接到外國不加分（紅閃「不是台灣味」）、漏接無事。emoji 故意有重複（如🍜），逼玩家讀名稱判斷——這才是知識測驗。
- **台灣味清單**取自本站菜單（珍奶/牛肉麵/蚵仔煎/雞排/臭豆腐/芒果冰/鳳梨酥/豆花/刈包/大腸蚵仔麵線/鹽酥雞/滷肉飯）；外國為披薩/漢堡/壽司/可頌/塔可/義大利麵…。
- **過關**：分數 ≥ 50 → win 畫面「關閉遊戲 →」→ 關閉覆蓋、解鎖捲動。隨時可按右上「關閉」或 **Esc** 離開（不再寫入 `sessionStorage` 過關旗標，因為遊戲已非鎖站門檻）。
- **純 DOM + requestAnimationFrame**（無 canvas、無套件）；落下物用 `createElement`+`textContent`（不進 innerHTML）。
- **無障礙**：方向鍵可控籃子、Esc 關閉；右上「關閉」逃生口避免無法操作者被卡死。`window.TAIGAME.launch()` / `close()` 供測試。

## 每日一食「今天吃啥?」（`#daily`）

解決「今天吃什麼」的選擇困難——擲骰隨機推薦一道台灣美食，搭配月曆每日紀錄。

- **隨機池**：全部 33 道（鹹+甜+飲）。
- **近三天不重複**：產生某天的菜時，把前 3 天的菜從候選池排除（`pool.filter(排除 recentIds)`）。
- **月曆預先填滿（重載不變）**：用 **FNV-1a 雜湊**把日期字串轉成穩定數字當索引（`hashStr(dateKey) % pool.length`）→ 每天的菜是確定性的，重整頁面結果一致；建月時從「月初前 3 天」連算到今天當緩衝，讓月初的三天規則也正確。
- **今天是互動日**：未擲 → 擲骰卡顯示 CSS 紅骰子、月曆今天格顯示「?」；按「擲骰！」用 `Math.random` 從候選（排除前 3 天＋當前）抽一道，slot-machine 輪播後定格，寫入 `localStorage['taifood_daily']`（`{日期:dishId}`）並更新月曆今天格；可「換一道」。
- **持久**：`localStorage` 記住真實擲過的日子；重整後今天顯示上次結果。點過去日格 → caption 顯示「5/28 吃了 · 蚵仔煎」。
- **無障礙/減動**：`prefers-reduced-motion` 下略過骰子晃動與輪播、直接出結果。手機雙欄改上下堆疊、月曆縮小。
- 結果卡的菜圖沿用 `data.js` 的 `img`（有照片用照片、無則 emoji），點「看詳情」進 `dish.html?d=<id>`。

## 甜點圓桌轉盤（釘住聚焦 + 滾動驅動旋轉）

甜點區不用傳統卡片格線，改成**圓桌轉盤**：

- **結構**：`#sweet` 內為高軌道 `.tt-track`（桌機 300vh／手機 260vh），內含 `position:sticky` 的 `.tt-sticky` 把圓桌**釘在「固定 header 以下」的可視區中央**（`.tt-sticky` 以 `padding-top:var(--nav-h)` 扣掉導覽列高度，避免頂端聚焦盤被 header 切到）；圓桌直徑 `--D:min(88vw,660px,66vh)` 同時受視窗高限制（矮螢幕自動縮小、不頂到 header）；盤子 `clamp(116px,16vw,168px)`。`.turntable` 內 8 個 `.tt-plate` 由 `script.js` 依 `DISHES`（cat==='sweet'）產生，沿圓周每 45° 一個，皆連到 `dish.html?d=<id>`。
- **旋轉**：捲動軌道進度 `p=(0→1)` → `--spin = p*360°`，寫進 `.turntable`，整盤旋轉一圈、8 道輪流到頂。
- **正立**：每盤三層 transform——`.tt-plate` 定位上盤（`rotate(--a + --spin) translateY(-R)`）、`.tt-plate__inner` 反轉 `rotate(-(--a + --spin))` 讓文字**永遠正立**、`.tt-plate__card` 以 `--s` 縮放。
- **聚焦**：JS 每幀算各盤螢幕角 `(--a + spin) mod 360`，最接近正上（0°）者加 `.is-front`（放大 1.28、金色光暈），中央 hub `#ttFront` 同步顯示該道名稱＋價格。
- **減動 fallback**：`prefers-reduced-motion` 時不釘不轉，`script.js` 直接在軌道內放回一般 `.dish-grid`（重用 `dishCardHTML`），`.tt-track.is-static` 讓高度恢復 auto、sticky 取消。

同時完整成品 `滷肉飯_all.png` 浮現定格，營造「食材合體成一碗」的效果；附「🍚 重新組裝」可重播。

- 設定在 `data.js` 的 `ASSEMBLY`（資料驅動：`{ result, pieces:[{file,tx,ty,rot,d}] }`，未來其他菜備齊分層也能套）。
- 為何用「聚攏淡出＋成品浮現」而非「逐層精準堆疊」：分層 PNG 雖同尺寸，但內容各自**置中、非預先定位**，
  直接 1:1 疊不會成形；用轉場把對位誤差藏起來，最終定格採畫師原本的正確成品圖，任何一幀都好看。
- `dish.js` 偵測 `ASSEMBLY[id]` 才渲染舞台；其餘菜維持一般大圖／emoji。`prefers-reduced-motion` 下直接顯示成品、不飛入。

> ⚠ 安全：詳情用 `innerHTML` 組裝，所有插入值（含菜名、食材、店家、網址參數）皆經 `escapeHtml()`；圖片路徑 `encodeURIComponent()`。

## 搜尋功能（假資料店家）

標題問「想知道哪裡有美食?」，因此搜尋必須能回答「**哪裡**」。`data.js` 內建一份
`RESTAURANTS` 假資料（約 25 筆，模擬後端；**未來換真 API 只需替換這份來源，render 不用動**）。

**資料結構**
```js
{ id, name, city, district,
  category: 'salty' | 'sweet' | 'drink',   // 鹹點 / 甜點 / 飲品
  dishes: ['牛肉麵', '滷肉飯'],             // 與菜卡同名，熱門標籤可直接命中
  rating: 4.7, price: '$$',
  hours: '11:00–21:00', note: '一句店家特色' }
```

**比對規則**
- **關鍵字**：比對 `店名 + 招牌菜 + 分類中文 + 特色`（小寫、含子字串）
- **同義詞**：`SYNONYMS` 表讓口語也能命中正式菜名／分類（珍奶→珍珠奶茶、飲料→飲品、小吃→鹹點、冰沙→芒果冰…）
- **地點**：比對 `城市 + 行政區`，雙向含子字串（輸入「台北」或「信義」都命中）
- 兩欄都填 → AND；只填一欄 → 用該欄；兩欄皆空 → 提示需輸入

**輸出**：`#results` 區渲染店家結果卡（店名／地區徽章／招牌菜 tag／★評分／價位／營業時間），
鹹甜飲三類用 `border-top` 顏色區分；0 筆顯示明確訊息；「清除搜尋」收合結果區並清空輸入。

> ⚠ 安全：結果卡用 `innerHTML` 渲染，所有插入值都經 `escapeHtml()` 轉義；使用者輸入的關鍵字只走 `textContent`，不進 `innerHTML`。

## 設計決策（為什麼這樣做）

### 1. Splash 改成「軟引導」而非強制門檻
原 1.png 寫「點擊開始」。但 web 上強制門檻 = 流失訪客。改為：
- 點擊 → 播放離場動畫，平滑進入主站
- 滾動 → 自動離場，內容直接呈現

### 2. 9.png 是設計藍本，整站照它做
9.png 是 UI 參考圖（navbar / 搜尋 / 標籤）。我用 HTML 重做，比直接貼圖更靈活、可響應。

### 3. 33 道菜，全部接素材
鹹點 19 + 甜點 8 + 飲品 6 = 33 道，每張卡含中英文名、台味敘述、估價。鹹甜接 `assets/foods/` 真實插畫；飲品有照片的 3 款（珍奶／青茶／木瓜牛奶）接 `assets/drinks/` 合成圖，其餘 3 款（冬瓜茶／豆漿／檸檬愛玉）用 emoji。芒果冰改用 `assets/foods/sweet/芒果冰/splash.png`（碗＋水花合成圖）。

### 5. 每張卡的「米色圓盤」是 CSS 畫的，不是圖
食物插畫多為米白背景，直接放紅底會「貼紙感」。CSS `radial-gradient` 模擬陶瓷盤底襯托插畫，邊界自然融合。飲品改成同樣的米色圓盤＋大 emoji，視覺秩序維持一致。

### 4. 錯誤完整顯示在前端
依用戶全域規則。任何 JS error 都會用紅底警示框顯示在右下角，含檔名行號。

### 6. Hero「食物爆炸拼貼」5 層堆疊
**不重貼 `assets/1.png`**——splash 已經用過那張，hero 改成把 `assets/foods/` 裡的 9 道精選食物炸開鋪在**右側**（左側標題欄淨空，提升可讀性）。Hero 從後往前共 5 層：

1. **`.hero__sun`** — 純 CSS radial-gradient 金色太陽，置於右上做主光源，緩慢呼吸動畫
2. **`.hero__grain`** — base64 SVG turbulence 噪點 + `mix-blend-mode:overlay`，模擬印刷品紙質
3. **裝飾層** — 雙層雲（`.hero__cloud--1/2`）＋ 三層漣漪（`.hero__ripple--1/2/3`），每層 `data-depth` 不同
4. **`.hero__feast`** — **9 道食物 PNG 散落於右側**（鹹點：牛肉麵、蚵仔煎、雞排、胡椒餅、滷肉飯｜甜點：芒果冰、豆花、糖葫蘆、芋圓地瓜圓），每張獨立旋轉、大小、進場方向；外加 `.hero__watermark` 品牌 LOGO 浮水印（opacity .08）藏在標題左後方當質感層
5. **內容層** — 標題、搜尋框、印章；標題用 `background-clip:text` 做金箔漸層 + `::before/::after` 兩層紅色重影製造立體感

關鍵手法：
- **雙層 div 結構解決 transform 衝突**：每張食物 `<div class="hero__food"><img></div>`，外層接視差（獨立屬性 `translate:var(--px) var(--py)`），內層接旋轉 + floating，互不覆蓋
- **食物只佈右側**：移除原本壓在標題與左下角的 5 張（原 6/7/8/13/14），讓左側標題欄淨空，解決「美食」二字被菜壓住的可讀性問題
- **`foodBoom` 階梯爆出**：9 張用 `--delay:60ms~720ms` 依序進場，每張從 `--from-x/--from-y` 自訂方向飛入，做出鏡頭聚焦感
- **`foodFloat` 異步浮動**：每張 `--float-dur:5.8s~8.5s` + `--float-delay:.1s~.9s` 不同，避免機械感
- **`data-depth:0.03~0.18`** 分布，相鄰兩張不同速，視差時自然散開
- 標題的「美食」使用 `data-text="美食"`，用 `content:attr(data-text)` 在偽元素複製做重影，HTML 不重複
- **背景漸層提亮**：金色光暈比例調高、紅色基底略亮，整體不再過暗
- 所有動畫在 `prefers-reduced-motion:reduce` 下停用

### 7. Safari（WebKit）抖動修正
Mac Safari 曾出現「整頁抖動」，根因與修法（Chrome 容忍這些寫法、Safari 不會）：

| 問題 | 原因 | 修法 |
|------|------|------|
| 全部食物圖閃爍抖動 | `@keyframes foodBoom` 結尾畫格引用 `var(--px)/var(--py)` 且 `fill:forwards`，JS 又以 60fps 改寫這兩個變數 → WebKit 反覆重算動畫 | 視差改走**獨立變換屬性** `translate:var(--px) var(--py)`（與 `transform` 互不干擾），keyframe 結尾改 `transform:none`，不再引用會被 JS 改寫的變數 |
| 滾動掉幀 | `wmSpin` 動畫 `filter:drop-shadow`（無法 GPU 合成，逐格全頁重繪），且浮水印 opacity .08 根本看不出脈動 | 直接移除 `wmSpin`，保留靜態 drop-shadow |
| 滾動掉幀 | `.hero__sun` 90vh 巨型元素掛 `blur(20px)` 還做 scale 動畫，每格重新點陣化 | 移除 blur（radial-gradient 本身已是軟邊，視覺等效） |
| hero 整塊重繪 | `.hero__grain` 的 `mix-blend-mode:overlay` 拖著下方動畫層 | 加 `transform:translateZ(0)` 自成合成層 |
| navbar 毛玻璃失效 | `backdrop-filter` 沒加前綴（Safari 18 前不支援裸寫） | 補 `-webkit-backdrop-filter` |
| 頁面頂端回彈時 hero 圖層跟著彈跳 | Mac Safari 橡皮筋過捲讓視差 progress 變負值 | `script.js` 視差 progress `clamp(0,1)` |

**鐵律**：被 JS 高頻改寫的 CSS 變數，**絕不放進 `@keyframes`**；高頻位移一律走獨立 `translate` 屬性（Safari 14.1+）。

### 8. Lite 模式（舊機自動降級）
寫法修正後舊 MacBook 仍抖——根因不同：**老 GPU 扛不動效果總量**（6 個無限動畫 + 14 個合成層 + 噪點混合 + 毛玻璃），寫法再正確也掉幀。解法是 **adaptive quality**：

- **偵測**（`script.js` 開頭）：載入後 1.5 秒用 `requestAnimationFrame` 實測 FPS，**< 34 fps** → `<html>` 加 `.is-lite`，結果存 `sessionStorage`（同分頁不重測）。用實測不用 UA 嗅探——判斷「這台機器扛不扛得動」，不是「是什麼瀏覽器」。
- **降級內容**（`styles.css` 底部 `html.is-lite` 區塊）：停掉所有**無限**動畫（splash／太陽呼吸、食物浮動、印章搖擺）、移除噪點混合層、視差停用（JS 監聽器同步早退）、毛玻璃改實色、陰影減量。**版面與內容完全不變**；一次性進場動畫（heroFadeUp、reveal）保留。
- 基線優化：食物圖雙層 drop-shadow 改單層（第二層金色光暈視覺上幾乎不可見，成本卻是雙倍）。

> 測試技巧：在 DevTools console 執行 `sessionStorage.setItem('taifood_lite','1')` 後重整即可強制預覽 Lite 模式；`sessionStorage.clear()` 還原。
